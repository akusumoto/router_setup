# MAP-E MTU change

Reviewed baseline on 2026-10-16 JST: `network.mape_auto` uses protocol `map`,
encapsulation limit `ignore`, no explicit MTU; active tunnel MTU was 1280.
Native WAN `eth0` and LAN `br-lan` are 1500. WAN-zone TCP MSS clamping is
enabled (`mtu_fix=1`). Firewall and DHCP require no change.
Live MAP rules, public addresses, and client inventories are intentionally
omitted. Verified recovery copies of network, firewall, and DHCP are under
`/root/mtu-test-20261016/` on the router; hashes are in the execution history.

Proposed sanitized configuration delta:

```diff
 config interface 'mape_auto'
+    option mtu '1460'
```

Apply only after temporary runtime testing and while LAN SSH is available:

```sh
uci set network.mape_auto.mtu='1460'
uci changes network
# Require the sole change to be network.mape_auto.mtu='1460'.
uci commit network
```

The runtime interface must already be tested at 1460; committing UCI does
not itself change its current MTU. Verify `uci get network.mape_auto.mtu`,
`cat /sys/class/net/map-mape_auto/mtu`, DF IPv4 ping with 1432 bytes of
payload, IPv4 HTTPS, IPv6, and DNS. No LAN or physical WAN MTU change.

Rollback to the original default without a network restart:

```sh
uci -q delete network.mape_auto.mtu
uci commit network
ip link set dev map-mape_auto mtu 1280
```

Reboot and future reprovisioning are separate acceptance checks. The
reconciler preserves the option when updating an existing section, but
deleting/recreating that section can remove this override; recheck then.
